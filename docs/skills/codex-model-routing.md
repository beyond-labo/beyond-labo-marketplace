# Codex Model Routing SKILL

Codex の親モデル、オーケストレーター、SubAgent を、タスクの難易度、曖昧さ、目的と受け入れ条件の明瞭さから選びます。

## いつ使うか

タスク開始時に使用モデルを決めたいとき、複雑な作業の親モデルを選びたいとき、SubAgent へ安全に分割できる単位を設計したいときに使います。
OpenAI API を組み込むアプリケーションの一般的なモデル選定や、画像・音声などの専用モデル選定には使いません。

## 前提条件

[Codex Model Routing プラグイン](../plugins/codex-model-routing.md)を導入し、新しいタスクで使います。
MCP、API キー、外部 CLI は不要です。
選択したモデルを実際に使えるかどうかは、Codex の実行環境とアカウントの提供状況に依存します。

## プロンプト例

```text
$codex-model-routing を使い、このタスクに適した親モデルと SubAgent のモデル構成を決めてください。
```

実行まで依頼する場合は、目的と受け入れ条件も渡します。

```text
$codex-model-routing を使って実行してください。目的は認証フローの回帰原因を特定して修正すること、受け入れ条件は対象テストと型検査が成功することです。独立した調査は Luna の SubAgent に委譲し、親モデルは難易度から選んでください。
```

## 選択基準

| 状況 | モデル |
| --- | --- |
| 目的、入力、出力、受け入れ条件が明瞭で、作業範囲を狭く閉じられる | GPT-5.6 Luna |
| 通常の実装、レビュー、調査 | GPT-5.6 Terra |
| 曖昧さ、依存関係、統合判断を含む複雑な統括 | GPT-5.6 Sol |
| 高度で長い推論を要する最難関の統括 | GPT-6 Astra |

Astra は、新規性の高い設計、複数領域にまたがる矛盾した制約、高い失敗コスト、長期的な整合性の維持が複数重なる場合に使います。
単に作業量が多い場合は、Astra へ上げる前に Sol で分解し、明瞭な単位を Luna へ渡します。

## SubAgent の方針

SubAgent は GPT-5.6 Luna で実行します。
委譲時に Luna を明示し、必要な文脈は委譲指示へ含めます。
実行環境で Luna の指定を保証できない場合は SubAgent を起動せず、親が作業を保持するか制約を伝えます。
各 SubAgent へ、目的、入力、対象範囲、対象外、期待する出力、受け入れ条件を明示します。

Luna に渡せるほど明瞭にできない難所は、より強い SubAgent へ変更せず、Sol または Astra の親が保持します。
親は結果を統合し、タスク全体の受け入れ条件に対して検証します。
並行化や文脈分離に実益がない場合は、SubAgent を使うためだけの分割を行いません。

## 入出力と責務

入力は、タスクの目的、受け入れ条件、未知事項、依存関係、失敗時の影響です。
出力は、親モデル、SubAgent の有無と担当、選択理由です。

利用者による明示的なモデル指定を優先します。
モデル選択によってタスクの権限や変更範囲は広がりません。
現在のタスクでモデルを変更できない場合や指定モデルを利用できない場合は、その制約と代替案を明示します。

実行規範の正本は、配布元リポジトリの `plugins/codex-model-routing/skills/codex-model-routing/SKILL.md` です。
