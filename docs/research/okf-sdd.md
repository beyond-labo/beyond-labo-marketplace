# OKF + SDD の構成と検証記録

## 作業基点と責務

2026-09-10 にリモートの既定ブランチを確認し、fetch 後の `origin/main`、`36dce07d1a582889441a2fb49b1bbb70aa1e0d34` を作業基点にした。
作業ブランチは `feature/okf-sdd`。
元プロジェクトの未コミット変更を含む18スキル、共通規則、16テンプレート、検査 CLI と18テスト、プロファイル、レビュアー定義を読み取り専用で参照した。

既存プラグインに仕様の進行・承認・知識同期の所有者はいなかった。
System Architecture Design は一般的な設計原則、Communication Writing は文章、Graphify / CodeGraph は探索を担うため、`.kiro` の状態を扱う本機能を `okf-sdd` としてまとめた。
新スキルの description は `.kiro` の仕様駆動開発を対象に限定した。
元の18スキル名を保ち、共通手順・プロファイル・テンプレート・依存・CLI を `kiro-spec-sync` に置いた。
同一だった steering の規則は `kiro-steering` に集約した。

## 配布用に変更した点

- 固定の `.agents/skills/` 参照を、インストールされたスキルの実パスから解決する方式に変更した。
- プロジェクト設定があれば確認して使い、欠けるテンプレートは配布資産から直接読めるようにした。
- 設定導入コマンドは既定で読取専用。適用時は欠落資産と、前回導入後に変更されていない資産だけを書き込み、利用者の変更を保持する。
- AGENTS.md、Codex 設定、spec.json、知識本文は設定導入の対象外とした。レビュアー定義は任意の参考資産にとどめた。
- batch の呼び出しだけで自動承認を推測する挙動を改め、`--auto` または既存の明示許可を条件にした。
- ハッシュ記録からの除外対象を `.kiro` 内の制御・索引・ログに限定した。bundle 外の `docs/index.md` などを明示依存として検出できるようにした。

## 実行した検証

Python 3.14 と PyYAML 6.0.3 のプロジェクト専用環境で24テストが成功した。
元の18テストに、配布と設定更新の5テスト、同名の外部依存を検出する1テストを追加した。

- 別ディレクトリへの配布物コピー、空白を含むパスからの CLI 起動とスキル間リンク解決。
- 16テンプレートのメタデータ生成、初期化テンプレートを使った仕様の検査。
- 読取専用の導入計画と検査、繰り返し導入、既存・利用者編集済み設定の保持、未変更の配布資産更新。
- 依存の推移的変更、追加・削除、不正参照、シンボリックリンク、状態不整合とハッシュ記録時の承認保持。
- 全18スキルの validator とプラグイン validator の成功。

独立したレビュー担当が配布構造を確認し、外部の `index.md` が除外される問題を再現した。
修正後に同じ例で変更検出と読取専用性を再確認し、指摘は解消した。
別の担当が隔離した仕様で以下を実操作した。

| 条件 | 結果 |
| --- | --- |
| 要件の誤字だけ修正 | CLI は変更を検出するが状態を変更しない。意味確認後の snapshot で記録を更新し、承認・完了・証拠を維持した。 |
| 上限10から20への要件変更 | 要件以降の承認と実装準備状態を無効化し、影響する完了タスクのみ再開した。未同期の設計・タスクを pending に残し、generated・phase・未知フィールドは維持した。 |
| briefだけを読取専用で点検 | 1文書・0仕様を検査し、ファイル集合と SHA256 は前後不変。spec.json は作成しなかった。 |

## 証明していないこと

テストと独立評価は隔離 fixture に対するもので、利用先の実仕様や実装が整合していることは証明していない。
意味変更の分類はモデルが実施し、CLI は構造と宣言されたローカル入力を確認する。
CLI が終了0でも `UNCHECKED` 警告や意味上の未同期があれば完了の証拠にならない。
外部 URL の更新、未宣言の依存、動的サービスの状態は別に確認する。
Python 3.10 以上を対象とするが、この記録の実行環境は3.14のみである。
Codex アプリへの実インストール、リモート公開、GitHub Pages の公開後確認は、このローカル検証に含まない。
