# kiro-spec-sync

.kiro の仕様駆動開発で変更を関連文書へ反映し、置換・撤回された旧要件や設計・タスクを削除して承認と完了状態を再評価する。仕様変更、実装完了、古い仕様の整理に使う。--check は読み取り専用の整合性点検。

## いつ使うか

このスキルは OKF + SDD の `.kiro` ワークフローで使います。
既存仕様に関係しない小修正は直接実施でき、すべての工程を通す必要はありません。

## 前提条件

`okf-sdd` v0.1.0 をマーケットプレイスから導入してください。
対象プロジェクトの関連文書、変更根拠、既存の承認範囲を確認します。
仕様がない段階では存在しない承認や完了状態を推測しません。
検査 CLI を使う場合は Python 3.10 以上と PyYAML 6.0.3 が必要です。
設定の準備と更新は [プラグインの導入手順](../plugins/okf-sdd.md) を参照してください。

## プロンプト例

```text
$kiro-spec-sync notifications --check 要件と設計の古い契約を読み取り専用で点検してください。
```

例の `notifications` は対象の feature 名へ置き換えます。
レビュー合格と工程承認、仕様の同期と実装完了は別々に扱います。
読取専用の依頼では本文・承認・索引を書き換えません。

## 古い仕様を整理する

```text
$kiro-spec-sync notifications 採用済みの保存先変更を反映し、置換された旧要件・設計・タスクと古い対象外条件を削除してください。関連仕様の参照・承認・索引も同期し、削除と保持の理由を報告してください。
```

日付や実装の不在だけで削除しません。未実装の有効な要件は保持します。
新しい feature へ責務を移した場合は旧 feature も調べ、全責務の撤回・移管と参照解消が確認できれば不要な文書を削除します。
経緯は短い変更記録に残し、旧本文は Git 履歴で参照します。
`--check` では削除候補を報告するだけで、本文や状態を更新しません。
