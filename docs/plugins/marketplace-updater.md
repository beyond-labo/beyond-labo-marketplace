# Marketplace Updater

別の作業環境で見つかった問題を、マーケットプレイス配布元のプラグインや SKILL の改善へ反映します。
インストール情報から配布元を特定し、最新のソースで修正と検証を行います。
PR 作成まで依頼されていれば、コミット、push、ドラフト PR の作成を続けます。

## 導入

[導入ガイド](../install.html)に従ってマーケットプレイスを追加し、`marketplace-updater` をインストールします。
登録済みの Git マーケットプレイスにまだ表示されない場合は、先に対象を更新します。
以下の `personal` は、このカタログをその名前で登録した場合の例です。

```bash
codex plugin marketplace upgrade personal
codex plugin add marketplace-updater@personal
```

新しいタスクから利用します。
マーケットプレイスのリポジトリを開いておく必要はありません。
対象スキルの配布元が確認できれば、改善用の作業コピーを別の場所に用意します。

## 構成と利用条件

| 項目 | 内容 |
| --- | --- |
| プラグイン | `marketplace-updater` |
| バージョン | `0.1.0` |
| カテゴリ | `DeveloperTools` |
| SKILL | [Marketplace Updater](../skills/marketplace-updater.md) |
| MCP、常駐処理 | 同梱なし |
| 必要な環境 | ローカルファイル操作、Git、配布元への接続、作業コピーの書き込み権限 |
| PR 作成時 | GitHub CLI `gh`、認証、ブランチ公開と PR 作成の権限 |
| 検証時 | 配布元が指定する validator と実行環境 |

GitHub 操作の手順には、導入済みなら [Git & GitHub Workflow](git-gh-authentication.md) を利用します。
未導入でも Git と `gh` による手順を持ちますが、認証や権限は別途必要です。
このプラグインは資格情報を保存せず、MCP 接続も追加しません。
ネットワーク接続先は、確認した配布元の Git ホストと PR 作成先です。

## プロンプト例

問題が起きた会話で、そのまま依頼できます。

```text
今回のように推測を断定へ変えてしまわないよう、$japanese-tech-writing 自体を改善して、配布元のドラフトPR作成まで進めてください。
```

Updater を明示して依頼する場合や、タスク中の継続的な改善を許可する場合の例は、[SKILL ガイド](../skills/marketplace-updater.md)にあります。

## 責務の境界

| 担当 | 責務 |
| --- | --- |
| Marketplace Updater | 利用中の問題と配布元を対応付け、別リポジトリでの改善から検証、許可済みの公開まで進める |
| `skill-creator` | 個々のスキルの設計、作成、修正 |
| `plugin-creator` | manifest とカタログの生成、ローカル開発版の更新 |
| Git & GitHub Workflow | 汎用のブランチ操作、認証、コミットと PR 作成 |
| 各業務スキル | 設計、文章、仕様など、利用元プロジェクトで依頼された作業 |

配布元の特定と作業環境をまたぐ改善が独立した責務であるため、個々の業務スキルや Git 操作のスキルへ共通手順を重複して追加していません。
既存プラグインの移動や改名はなく、移行作業は不要です。

自動選択は、実行中のタスクで改善依頼や継続許可を解釈して行います。
バックグラウンドで全タスクを監視する機能ではありません。
通常の利用だけを理由に、スキルを書き換えたり PR を公開したりしません。
一度依頼された範囲の許可は保持し、公開前に同じ確認を繰り返しません。

ソースの修正や PR 作成だけでは、インストール済みのスキルは更新されません。
配布ブランチへの取り込み後に対象マーケットプレイスを更新し、再インストールした状態を新しいタスクで確認します。
利用条件は配布元リポジトリの `README.md` に従います。
