# Codex Model Routing

必要十分な能力を持つ最小のモデルを選び、難しい判断は親へ、境界の明瞭な実行は Luna へ寄せる。
モデル選択は、依頼の範囲、権限、外部変更の許可を広げない。

## モデルの役割

| モデル | 選ぶ状況 |
| --- | --- |
| `gpt-5.6-luna` | 目的、入力、出力、受け入れ条件が明瞭で、作業範囲を狭く閉じられるタスク。定型変換、限定的な調査、指定済み設計の実装、個別テストなど。 |
| `gpt-5.6-terra` | 通常の第一候補。一定の判断を要する実装、レビュー、調査を、性能とコストの均衡を取りながら進めるタスク。 |
| `gpt-5.6-sol` | 曖昧さ、複数段階、依存関係、統合判断を含む複雑なタスク。特に、計画、分解、SubAgent の統括、結果の統合と検証を担うオーケストレーター。 |
| `gpt-6-astra` | Sol よりさらに難しく、高度で長い推論を要するタスク。新規性の高い設計、複数領域にまたがる矛盾した制約、高い失敗コスト、長期的な整合性の維持が複数重なる場合。 |

通常は Terra または Sol を使う。
明瞭で境界の狭いタスクには Luna を使う。
Astra は「難しそう」という印象だけでは選ばず、上記の高難度シグナルが複数ある場合、または利用者が明示した場合に選ぶ。

## ルーティング

1. 利用者がモデルを明示していれば、その指定を優先する。
2. 目的、受け入れ条件、未知事項、依存関係、失敗時の影響を確認する。
3. 単独で完結する明瞭な作業は Luna、通常作業は Terra、複雑な統括は Sol、例外的な高難度推論は Astra に割り当てる。
4. 複雑なタスクを委譲する場合、親は Sol を使う。Astra の条件を満たす場合だけ、親を Astra に上げる。
5. 親は SubAgent の結果を統合し、依頼全体の受け入れ条件に対して検証する。

現在のタスクでモデルを切り替えられない場合は、切り替えたふりをしない。
モデル指定が可能な新しいタスクまたは SubAgent にルーティングを適用し、現在のモデルとの差が結果に影響するときだけ利用者へ伝える。
指定モデルが利用できない場合も、黙って別モデルへ置き換えず、利用できないモデルと代替案を明示する。

## SubAgent

SubAgent を使う場合は `gpt-5.6-luna` で実行する。
委譲ツールがモデル指定を受け付ける場合は、SubAgent ごとに `gpt-5.6-luna` を明示する。
モデル指定のために継承する会話量を制限する必要がある場合は、必要な文脈を委譲指示へ含め、全履歴の暗黙継承に依存しない。
Luna の指定を保証できない実行環境では SubAgent を起動せず、親が作業を保持するか、制約を利用者へ伝える。
委譲する指示には、少なくとも目的、入力、対象範囲、対象外、期待する出力、受け入れ条件を含める。

Luna へ渡せる粒度まで作業を分解できない難所は、強いモデルの SubAgent へ変更せず、Sol または Astra の親が保持する。
SubAgent を使うためだけに分割しない。
互いに独立した探索、変換、限定実装、テストなど、並行化または文脈分離に実益がある場合に委譲する。

## 選択結果の伝え方

モデル構成を求められたときは、親モデル、SubAgent の有無と担当、各選択の根拠を簡潔に示す。
実作業を依頼されたときは、この方針を内部の実行計画へ反映し、モデル説明だけで作業を止めない。
